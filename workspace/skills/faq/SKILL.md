# FAQ 知识库查询

## 知识来源

知识库为 workspace 根目录下的 `knowledge/ikea/general.md`。此路径相对于 workspace，使用 `read_file` 读取时从 workspace 定位。

文件包含购物与售后 FAQ、退货政策详情，以及开头的来源差异说明。来源链接与抓取时间随正文保存。回答依据实际读取的内容，保留其中的购买渠道、商品类别和适用条件。

## 查询流程

1. 结合当前会话识别用户意图，区分政策咨询、操作指导和实际订单状态查询。复用用户已经提供的信息。
2. 使用 `read_file` 读取 `knowledge/ikea/general.md`。先检查来源差异说明，再定位相关条目。如果工具输出被截断，继续读取相关部分，覆盖该问题涉及的条件和例外。
3. 按关键词定位、理解语义和合并相关条目的方式匹配问题。涉及退货或退款时，同时核对 FAQ 和退货政策详情。
4. 判断文档是否能支持答案。缺少会改变判断的信息时，追问商品类型、购买渠道、签收时间、商品状态或退货原因中的必要项。一般政策咨询可先说明条件，无需先索取订单号和联系方式。
5. 给出有依据的结论、适用条件和下一步，并引用对应的原始页面。资料仍不足、用户尝试后未解决，或用户要求人工时，按下方工单衔接规则处理。

## 匹配策略

- 关键词定位时，关注退货、换货、退款、运费、取消、物流、少件、错发、破损等表达。
- 语义匹配时，将“买错了”“不想要了”“尺寸不合适”等表达关联到可能的退货场景，再根据具体条件核对条款。
- 多条目合并时，结合退货资格、运费承担、申请方式和退款时限回答复合问题，并保留每项结论的来源。
- 找到相关关键词后，仍需检查条款能否适用于当前问题。知识库没有覆盖的商品特例、金额或时限，应说明需要核实。

## 特殊情况

- 文档对退款办理时限和取消订单条件存在差异。已确认的口径差异：FAQ 页面写“收到退货确认无误后 7 个工作日内办理”，退货政策详情写“7 日之内”。遇到相关问题时，说明具体差异及来源，并建议向官方客服核实；避免自行选定一个时限作为承诺。同时区分“办理退款手续的时限”和“实际到账时间”，后者取决于原支付方式的服务平台。官方客服热线 400-800-2345。
- “怎么查物流”“如何查询退款”可以依据文档说明路径。“我的包裹到哪了”“我的退款到账了吗”需要实际订单工具。工具可用时转入相应查询流程；尚未接入时说明情况，并提供文档中的自助查询路径。
- 页面中的活动时间和服务时间属于抓取时的快照。遇到“今天是否营业”等时效问题，说明需要核实当前信息。
- 文件不存在、读取失败或相关内容无法完整取得时，说明暂时无法核实知识库答案。仍有其他步骤可读时先完成读取。

## 回复组织

使用用户当前使用的语言。普通问题简洁回答，操作指导使用有序步骤；资料中的产品名、订单状态和必要条件保持准确。

通常包含结论、必要条件、可执行的下一步，以及段落末尾的来源链接。来源使用正文中实际存在的官方 URL，避免把本地文件路径作为用户的参考链接。

信息不足时，简短说明需要确认什么，并提出当前最关键的问题。存在多种适用情况时，可以先给出条件式回答，再请用户补充。

## 工单衔接

- 文档未覆盖、处理步骤未解决问题或用户提出人工请求时，先说明当前已知情况。
- 工单能力可用且用户尚未同意时，询问是否创建本项目的人工支持工单。用户已经明确要求建单时，直接收集必要信息。
- 用户同意后，使用实际存在的工单 Skill 和 MCP 工具完成创建。将问题、已尝试步骤和相关来源整理为摘要，避免让用户重复描述。
- 工单能力尚未接入时，说明当前可帮助整理问题，并给出知识库中的官方联系渠道。
- 以工具成功结果为依据确认工单创建，回复真实工单号。工单属于本项目时向用户说明其归属，实际退货、退款和官方人工受理结果需要对应业务能力确认。

## 示例判断

| 用户问题 | 处理方式 |
| --- | --- |
| 收纳盒不合适可以退吗？ | 查退货条件，按需要确认签收时间、购买渠道和货品状态 |
| 杯子碎了，能帮我处理吗？ | 查破损或错漏配送条目，说明文档中的处理步骤，再根据用户意愿进入工单流程 |
| 退款一定七天到账吗？ | 核对两份来源的时限差异，并说明办理退款与实际到账需要分别确认 |
| 我的退款到哪一步了？ | 判断是否有实际查询工具，按能力提供查询结果或自助查询路径 |
